# Work Log - 2026-04-27

## Summary

Today the ClawHub repository moved from an early admin-only MVP skeleton to a real control-plane baseline with:

- user registration and login
- role separation between `ADMIN` and `USER`
- user-owned instance management
- one-user-one-instance enforcement
- global platform capacity limit of `5` instances
- frontend rebuilt from a temporary static page into a `Vue 3 + TypeScript` app

The work stayed on the ClawHub control plane side. No QwenPaw business logic was moved into this repository.

## Product Rules Finalized

The following product rules were agreed and implemented:

- public registration is allowed
- registered users default to role `USER`
- platform roles are only `ADMIN` and `USER`
- `USER` can create, view, open, start, stop, restart, and delete only their own instance
- `USER` can have at most one instance at a time
- if a `USER` already has an instance, creating another one is rejected directly
- platform-wide total instance count is limited to `5`
- the `5`-instance limit includes both admin-created and user-created instances
- `ADMIN` can manage all users and all instances

## Build and Deployment Flow Updated

The deployment flow was changed to:

1. build frontend assets first
2. package Spring Boot jar
3. build Docker image from packaged jar

This was necessary because the frontend is now a real separate source tree and the Docker image no longer builds frontend assets automatically.

Current build flow:

```bash
cd frontend
npm install
npm run build

cd ..
mvn -DskipTests package
docker build -t clawhub:mvp .
```

## Operational Findings

Several deployment/build issues were encountered and resolved:

- building Docker image with `apt-get install docker.io` failed because of network/proxy instability
- solution: remove in-image Docker installation and reuse host `/usr/bin/docker` plus `/var/run/docker.sock`
- building app fully inside Docker failed because Maven Central access inside build container was unstable
- solution: build frontend and jar outside Docker first, then build image from packaged artifact
- old ClawHub data is not assumed compatible with the new auth/ownership schema
- safest upgrade path is to reset ClawHub control-plane data and reinitialize
